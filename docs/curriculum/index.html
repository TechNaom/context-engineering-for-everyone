Roadmap

The course mirrors the `ai-engineering-for-everyone` architecture: chapters grouped into modules, each ending with exercises, a practice bank, interview prep, a project, and a builder thought-process journal. Hands-on chapters that need a real model run against Ollama by default — zero API cost, zero API key — with a documented option to swap in a hosted provider instead.

Module 1: The Context Budget Mental Model

What the context window actually is, and the budget discipline that governs everything else in this course.

Outcome: diagnose a real system's context-budget misallocation; allocate a token budget across sources for a given request type.

Module 2: Memory Systems

What a system remembers between turns, and between sessions.

Outcome: design short-term memory that stays in budget; design a long-term memory system with a real retrieval-into-context policy.

Module 3: Context Compression and Curation — Complete

Making the most of a limited budget: what to compress, and where in the window it goes.

Outcome: compress/summarize context without losing load-bearing content; order context to avoid lost-in-the-middle degradation.

Module 4: Multi-Source Context Assembly — Complete

Combining retrieved documents, tool outputs, conversation history, and system instructions into one coherent context.

Outcome: assemble multi-source context without contradiction; integrate a RAG pipeline's ranked results into context correctly.

Module 5: Context Engineering for Agentic Systems — Complete

What context a step, a tool call, or a sub-agent actually needs — not everything, by default.

Outcome: engineer context for a tool call; engineer context across a multi-step/multi-agent pipeline with deliberate isolation.

Module 6: Evaluation and Capstone — In Progress

Is the assembled context actually good, and can you defend a complete context engineering system end to end.

Outcome: evaluate context quality before it reaches the model; design and defend a complete context engineering system.

Chapter 10 ships no project of its own either — Module 5's own two labs still fold into the Chapter 13 capstone, not a per-chapter project. Chapter 11 is now live too, closing Module 5 in full: it engineers the deliberate flip side of Chapter 10's own recipe — when withholding context between two steps or agents is the correct design choice on purpose, rather than a scoping bug, naming that isolation goal specifically, drawing the boundary around a prior agent's own opinion rather than its entire step, handing shared facts across the boundary through an explicit curated contract, and testing the result with both a contamination probe and a starvation probe. Chapter 11 ships no project of its own either; Module 5's own project ladder still assigns no dedicated slot, folding both of its labs into the Chapter 13 capstone. Module 5 (Context Engineering for Agentic Systems) is now complete across Chapters 9-11. Chapter 12 is now live too, opening Module 6 (Evaluation and Capstone): for the first time since Chapter 1, it is not about producing context correctly but about measuring whether context Chapters 1-11 already assembled correctly is actually good — scoring fact-level completeness against a specific required-fact list rather than source presence, computing a real noise ratio, auditing where each required fact actually landed against Chapter 6's own re-verified Lost-in-the-Middle findings, and combining all three into one pre-call quality gate, re-run whenever the assembly pipeline itself changes. Chapter 12 ships no standalone L-tier project of its own, but does ship the Module 6 assessment the curriculum map names directly — a context-evaluation exercise in assessments/module-assessments/. Chapter 13 is scaffolded (a `.gitkeep`'d directory under chapters/) and planned per CURRICULUM_MAP.md as the Level 4 capstone, not yet built — see PROJECT_STATE.md for the current, authoritative build status and the next recommended session's task.
