Why This Course Is Different

Owns the Dynamic Content, Not the Static Template

`ai-engineering-for-everyone` Chapter 3 versions the prompt template as a software artifact. This course assumes that's already done, and engineers what fills the template's variable slots fresh, on every single request.

Context Is a Finite, Costed Resource

Not "more context is better" — every token in the window competes with every other token for a limited budget, and model accuracy degrades well before the window's hard limit is even reached.

Position, Not Just Presence

A fact can be technically included and still functionally lost — where something sits in the window changes whether the model actually uses it. No sibling course teaches this as a first-class subject.

Open roadmap

Chapters 1-12 are live end to end — lesson, quiz, exercises, practice bank, and interview prep each, plus a full graded project for Chapters 1-4, Chapter 6, and Chapter 8. Chapters 1-2 complete Module 1 (The Context Budget Mental Model); Chapters 3-4 complete Module 2 (Memory Systems) in full, building the real eviction/compression policy that keeps one conversation's history inside its token budget (Chapter 3), then the real write and retrieval policy that decides what a system persists across sessions and what comes back into context for a given turn (Chapter 4's L2 Assisted project, closing the module). Chapters 5-6 complete Module 3 (Context Compression and Curation) in full: Chapter 5 engineers the real mechanics a compression call uses to decide what survives when content no longer fits its budget, and Chapter 6 engineers where already-included content should sit inside the assembled window, re-verifying the "lost in the middle" finding against current research and closing the module with a single joint project spanning both chapters. Chapters 7-8 complete Module 4 (Multi-Source Context Assembly) in full: Chapter 7 engineers how several sources — retrieved documents, live tool output, conversation history, system instructions — get combined into one window without silently contradicting or crowding each other out, and Chapter 8 engineers the handoff Chapter 7 left open on purpose, turning a retriever's own raw ranked, scored output into one well-formed source before it ever reaches Chapter 7's own inventory step — closing the module with a single L3 Independent project spanning both chapters, the curriculum map's own literal L3 tier. Chapter 9 is now live too, opening Module 5 (Context Engineering for Agentic Systems): it engineers what a tool call already assumed a protocol correctly delivered — scoping which tool definitions actually belong in context for a given request type, budgeting each included schema as its own line item, curating and boundary-safely fitting a tool's raw result, and evicting or marking superseded tool-call history across a multi-step loop, all handed off to Chapter 7's own Source Assembly Recipe as one well-formed tool_result source. Chapter 10 is now live too, continuing Module 5: it engineers the same "what does this step actually need" question at pipeline scale — defining each pipeline step's own scoped context contract, passing prior steps' outputs as curated results, budgeting each step as its own ledger line, isolating context at every unit-of-work boundary so one case's own resolved findings never bleed into the next, and giving each sub-agent only its own delegated sub-task rather than an orchestrator's full session history. Chapter 11 is now live too, closing Module 5 in full: it engineers the deliberate flip side of Chapter 10's own recipe — when withholding context between two steps or agents is the correct design choice on purpose (an independent second opinion, a reduced blast radius, a bias firewall), naming that isolation goal specifically, drawing the boundary around a prior agent's own opinion rather than its entire step, handing shared facts across the boundary through an explicit curated contract, and testing the result with both a contamination probe and a starvation probe — because a boundary drawn for exactly the right reason can still starve a downstream step of something it legitimately needed. Chapters 9, 10, and 11 all ship no project of their own — the curriculum map's own ladder assigns no project slot to Module 5 at all; its labs fold into the Chapter 13 capstone instead. Module 5 (Context Engineering for Agentic Systems) is now complete across Chapters 9-11. Chapter 12 is now live too, opening Module 6 (Evaluation and Capstone): for the first time since Chapter 1, it is not about producing context correctly but about measuring whether an already-correctly-assembled bundle is actually good — scoring fact-level completeness against a specific required-fact list rather than source presence, computing a real noise ratio instead of trusting that fitting a budget means the budget is well spent, auditing where each required fact actually landed against Chapter 6's own re-verified Lost-in-the-Middle findings, and combining all three into one pre-call quality gate re-run whenever the assembly pipeline itself changes. Chapter 12 ships no standalone L-tier project of its own, but does ship the Module 6 assessment the curriculum map names directly — a context-evaluation exercise in assessments/module-assessments/. Chapter 13, the Level 4 capstone, is planned and scaffolded (see the roadmap), closing Module 6 and the entire course. The sidebar and this chapter map are connected to the same course data.
