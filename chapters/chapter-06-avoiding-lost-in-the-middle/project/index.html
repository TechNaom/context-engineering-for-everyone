Module 3 Project ~60 min

Project: Build Brackholt's ArchiveLine Compression + Ordering Pipeline

Brackholt County Court Records Office's fictional docket-review assistant, ArchiveLine, helps a public defender review an active case file before a hearing. This is Module 3's closing lab, drawing on both chapters this module built — Chapter 5's Compression Fidelity Recipe and Chapter 6's own Context Ordering Recipe — per the curriculum map's own paired Module 3 labs. You design both halves at once: compressing an aged-out conversation segment without losing what it must preserve (Chapter 5's skill), and deciding where every already-included content block belongs in the final assembled window (this chapter's own skill).

A note on this project's tier The curriculum map's own four-tier project ladder doesn't assign a numbered tier to Module 3 — it jumps from L2 (Ch. 4) to L3 (Ch. 8). This project fills that gap under this course's own "one project per module" convention, sitting between L2's partial scaffold and L3's no-scaffold: a full spec is given, but no part is solved for you. See quality-audits/chapter-06-audit.md for the full reasoning.
How to run it Download starter.py, fill in your Part 1 (compression) and Part 2 (ordering) choices and both write-ups, then run python3 starter.py. Most of this project's self-check is fully mechanical — it verifies your Part 1 candidate/strategy choices, and separately verifies your Part 2 block placements against the anchor/middle rules and the assembled window's budget. Compare against solution.py, then self-grade against RUBRIC.md.
starter.py solution.py (reference) RUBRIC.md README.md

What you're given

A 3,000-token raw segment that must compress to a fixed 600-token target, with three already-flagged load-bearing candidates; a 3,200-token assembled-window budget containing six already-correctly-included content blocks (two high-weight, three low-weight, one query), each tagged with its own token count.

What you produce

A valid compressed-candidate set and strategy choice per candidate that preserves all three flagged details; a valid block-position assignment that reserves both anchor positions for the highest-weight content and the active query, leaves every low-weight block in the middle, and fits the window budget; and two defended write-ups, one per part.

Passing bar

19/24 (about 80%) or higher on RUBRIC.md's six criteria, with no single criterion scoring 0. solution.py is one complete, valid reference design scoring a full 24/24 — not the only correct design, since the compressed wording and both write-ups are intentionally open.
