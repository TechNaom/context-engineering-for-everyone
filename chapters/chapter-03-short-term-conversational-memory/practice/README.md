# Chapter 3 Practice Bank: Short-Term Conversational Memory

Eight short, independent scenarios, each its own fictional system —
none of them Emberlynn Transit Cooperative/RouteLine or Quarrowstead
Legal Aid Partners/DocketLine again. Each scenario is a few sentences
and one judgment or arithmetic question about *keeping conversation
history inside an already-allocated Line 3 budget*, not deriving the
budget itself (that's Chapter 2's job). The point is speed and
accuracy across many different systems, the way a real short-term
memory policy review actually feels.

## How to run

```bash
python3 starter.py
```

Fill in each `# TODO`, re-run, and watch your score climb.

## The eight scenarios

1. **Larkmoth Outdoor Retail (judgment)** — does raising Line 3's token
   budget alone fix a forgotten early fact, without a real policy?
2. **Feldspar Municipal Water Utility (production-gear)** — verbatim
   window sizing arithmetic after pinned-fact and summary reserves.
3. **Pemberglen Veterinary Partners (judgment)** — should a pinned-fact
   reserve be allowed to grow without any size limit?
4. **Sootmarsh Freight Cooperative (production-gear)** — find the turn
   where a compression trigger threshold is first reached.
5. **Glennoak Wealth Advisors (judgment)** — is continuous, from-turn-1
   summarization a good default?
6. **Tarnwick Community College (production-gear)** — pin/no-pin call on
   a single safety/eligibility-relevant disclosure.
7. **Hushfield Telehealth Network (production-gear)** — does a built
   memory package fit inside its Line 3 budget?
8. **Vallowmere Grocery Cooperative (judgment)** — does adding a
   compression policy remove the need for worst-case validation?
