Practice Bank: Designing Context Window Budgets

Eight short, independent scenarios, each its own fictional system — none of them Vantry Health Network/TriageLine or Corravine Freight/DispatchLine again. Each scenario is a few sentences and one judgment or arithmetic question about allocating a budget, not diagnosing one already broken. The point of this bank isn't depth on one system — it's speed and accuracy across many different systems, the way a real pre-launch budget review actually feels.

Practice standard Eight scenarios. Two are pure judgment calls (Scenario 5 asks whether a bigger window removes the need to allocate; Scenario 6 asks whether a matching profile shape alone is enough to safely reuse a budget) and two are production-gear arithmetic (Scenario 7 derives a real token allocation; Scenario 8 finds a real deficit from allocated-vs-actual numbers).
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect 8/8.

Scenario 1

Marrenkirk Insurance Group

A claims-review assistant adds a new "Document-Heavy Claim Review" request type, where one large uploaded claim file dominates almost every request, with little conversation history or persisted memory involved. Which archetype profile fits this request type?

Scenario 2

Duvane Utilities Cooperative

An outage-report assistant's team allocates Lines 1 through 4 carefully, then lets the model's response use "however much is left over," reserving nothing up front. Which recipe step did they skip?

Scenario 3

Graytide Hospitality Group

A booking-concierge assistant's team computes the Line 2/3/4 split first, using the full context window as the base, and only afterward subtracts Line 1's tokens from whatever's left. Is this ordering still correct?

Scenario 4

Oakspire Home Care Network

A caregiver-scheduling assistant's team tests their new budget only against typical, average-length conversations, and never checks it against the longest real conversations in their own data. Which recipe step did they skip?

Scenario 5 · Judgment

Corundale Media Group

A content-review assistant's team upgrades from a 16,000-token model to a 128,000-token model and declares "our budget allocation problem is solved, no more per-request-type work needed." Is this reasoning sound?

Scenario 6 · Judgment

Pallisade Manufacturing

Two request types happen to share the same archetype profile. A teammate argues this means it's safe to copy one request type's exact numeric token budget onto the other without re-deriving anything. Is this safe?

Scenario 7 · Production-gear

Redcliff Credit Union

A fraud-review tool-dispatch assistant runs on a 24,000-token window, reserving 2,000 tokens for output and 800 for system instructions. Using the tool-heavy profile, what is the Grounding Context (L2) allocation, in tokens?

Scenario 8 · Production-gear

Thackery Regional Exchange

A shipped budget allocated L2=9,000, L3=6,000, L4=3,000 tokens. A worst-case audit finds the actual need is L2=7,000, L3=8,200, L4=2,500 tokens. Which single ledger line is genuinely under-provisioned?
