Chapter 2 Project · L1 Guided ~45 min

Project: Design Halveston's Post-Discharge Follow-Up Budget

Halveston Regional Health System's fictional patient-messaging assistant, IntakeLine, is shipping a new request type: "Post-Discharge Follow-Up," a recurring, memory-heavy conversation. You're given the real spec — a fixed window, a fixed output reservation, a fixed system-instructions cost, and worst-case content-audit numbers per line. Your task: allocate the remaining budget across three lines, validate your allocation against the worst case, and plan a follow-up for anything that comes up short.

Why this project, not another diagnosis task Chapter 1's project tested whether you could look at an existing system and correctly name what's missing. This chapter's own skill is earlier in the lifecycle: given a request type that doesn't exist yet, can you derive a real, defensible token budget for it before a single request ships — the exact step this chapter's own hook, Vantry Health Network's TriageLine, skipped for its second request type.
How to run it Download starter.py, fill in the allocation, validation, and follow-up plan, then run python3 starter.py. Most of this project's self-check is fully mechanical — it verifies your allocation sums correctly and that your own surplus/deficit calls are internally consistent with your own numbers. Compare against solution.py, then self-grade against RUBRIC.md.
starter.py solution.py (reference) RUBRIC.md README.md

What you're given

A 48,000-token context window, a fixed 2,500-token output reservation, a fixed 1,200-token system-instructions cost, and a worst-case content audit's real token needs for Grounding Context, Conversation History, and Recalled Long-Term Memory.

What you produce

A token allocation across the three remaining lines that sums to the real remaining budget, a defended profile justification, a correct surplus/deficit classification for each line against your own numbers, and a concrete follow-up plan for anything in deficit — the same shape as the lesson's own TriageLine worked math, applied by you, to a fresh system.

Passing bar

16/20 (80%) or higher on RUBRIC.md's five criteria, with no single criterion scoring 0. solution.py is one complete, valid reference allocation scoring a full 20/20 — not the only correct split, since the profile choice is intentionally open-ended.
