Chapter 2 Exercises ~45 min, hands-on

Exercises: Designing Context Window Budgets

These exercises use a second scenario, deliberately different from the lesson's Vantry Health Network/TriageLine hook: Corravine Freight, a fictional freight-dispatch company. Its internal dispatcher assistant, DispatchLine, serves several distinct request types on the same 16,000-token model. Applying the five-step allocation recipe to fresh request types is the point; recalling the lesson's own numbers by heart won't get you through these.

Exercise standard Eight tasks total. Six are marked production-gear — budget subtraction, profile-split arithmetic, worst-case validation, reuse-safety judgment, from-scratch allocation design, and a recipe completeness gate, not just concept recall.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect total.
starter.py solution.py (reference)

1 Match request types to profiles

Assign the correct archetype profile (short lookup, long recurring, tool-heavy, long-document) to four DispatchLine request types, based on each one's actual content shape.

2 Order the allocation recipe steps

Put the lesson's five allocation-recipe steps in the correct sequence, from fixing the hard limit to validating the worst realistic case.

3 Production-gear Reserve output + system, compute remaining budget

Given Quick Status Lookup's window, reserved output, and system-instructions sizes, compute the real remaining budget for Lines 2, 3, and 4.

4 Production-gear Profile-split arithmetic

Split Exercise 3's remaining budget across Lines 2, 3, and 4 using the short-lookup profile's percentages.

5 Production-gear Worst-case validation

Given an already-computed allocation and a real worst-case need for each line, classify each line as surplus or deficit.

6 Production-gear Reuse-safety judgment

Decide whether it's safe to reuse Quick Status Lookup's budget for the differently shaped Multi-Leg Route Exception Review request type.

7 Production-gear Design a new allocation from scratch

Apply the full five-step recipe to Full Manifest Audit, a brand-new request type on a larger, 32,000-token-window model.

8 Production-gear Recipe completeness gate

Confirm all five recipe steps were actually applied while working through Exercises 1–7 — the same completeness discipline a real team runs before a new request type's budget ships.
