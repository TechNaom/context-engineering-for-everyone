Chapter 4 Project · L2 Assisted ~55 min

Project: Design Brightmoor's CaseLine Short-Term AND Long-Term Memory

Brightmoor Elder Law Group's fictional case assistant, CaseLine, supports a guardianship case that has run across many separate sessions over more than a year. This is Module 2's closing lab — the curriculum map's own "L2 Assisted" project, shipped once, solo, per the reasoning in quality-audits/chapter-04-audit.md. You design both halves at once: the short-term policy for the currently open session (Chapter 3's skill), and the long-term retrieval policy for what gets pulled back in from prior, closed sessions (this chapter's own skill).

Why this project touches both lines A partial-scaffold "Assisted" project is deliberately less hand-held than Chapters 1-3's fully guided L1 projects. A real long-term memory review never happens in a vacuum — it happens alongside an already-open session's own short-term policy. This project tests whether you can hold both constraints (Line 3's budget for this session, Line 4's budget for what crosses in from before) at once, without either one silently breaking the other.
How to run it Download starter.py, fill in your Part 1 (short-term) and Part 2 (long-term) choices and both write-ups, then run python3 starter.py. Most of this project's self-check is fully mechanical — it verifies your short-term pins and budget exactly as Chapter 3's project did, and separately verifies your long-term retrieval choices against required/forbidden categories and the staleness-exclusion rule. Compare against solution.py, then self-grade against RUBRIC.md.
starter.py solution.py (reference) RUBRIC.md README.md

What you're given

A 3,800-token Line 3 budget and a fixed 900-token summary for the currently open session (10 real turns, 5 candidate facts); a 250-token Line 4 budget and a persistent store of 6 fact records already written from prior sessions, each tagged with a category and a status (active, superseded, or expired).

What you produce

A valid short-term pin set and verbatim window that fits Line 3; a valid long-term retrieval set that includes every required active record, excludes every forbidden or non-active record, and fits Line 4; and two defended write-ups, one per line.

Passing bar

19/24 (about 80%) or higher on RUBRIC.md's six criteria, with no single criterion scoring 0. solution.py is one complete, valid reference design scoring a full 24/24 — not the only correct design, since both administrative judgment calls (the short-term pin, the long-term retrieval) are intentionally open.
