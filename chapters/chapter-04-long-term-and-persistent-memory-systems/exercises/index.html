Chapter 4 Exercises ~45 min, hands-on

Exercises: Long-Term and Persistent Memory Systems

These exercises use a second scenario, deliberately different from the lesson's Nightbourne Senior Living Network/HearthLine hook: Caldermere Home Health Alliance, a fictional home health agency. Its aide-support assistant, CareLine, works with recurring clients across many separate visits on a model with a correctly allocated 1,800-token Line 4 budget. Building the real write and retrieval policy that keeps that budget honest across a real, changing relationship is the point; the budget number itself is already given.

Exercise standard Eight tasks total. Six are marked production-gear — uncurated-growth arithmetic, retrieval budget sizing, write/no-write classification, staleness resolution, package validation, and a naive-append-vs- curated regression gate, not just concept recall.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect total.
starter.py solution.py (reference)

1 Match scenarios to long-term memory approaches

Decide which of three CareLine scenarios need no persistent memory, which need a curated store, and which show the append-only anti-pattern.

2 Order the Long-Term Memory Policy Recipe

Put the lesson's six policy steps in the correct sequence, from write criteria to worst-case validation.

3 Production-gear Uncurated growth, first visit over budget

Compute cumulative token totals across a growing, uncurated fact store and find the first visit that exceeds the 1,800-token budget.

4 Production-gear Retrieval budget sizing

Compute how many additional facts a turn's retrieval can afford once a core reserve is subtracted from the budget.

5 Production-gear Write/no-write classification

Decide which facts from a real CareLine client relationship are durable enough to persist at all.

6 Production-gear Staleness resolution

For facts that changed over time, determine which version stays active and which is superseded.

7 Production-gear Build and validate the retrieved Line 4 package

Verify a core-facts-plus-scoped-facts retrieval actually fits inside the Line 4 budget.

8 Production-gear Naive-append-vs-curated regression gate

Confirm a superseded fact that a naive "retrieve everything ever stored" policy would incorrectly surface is correctly excluded by the curated policy.
