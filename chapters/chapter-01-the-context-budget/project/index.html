Chapter 1 Project · L1 Guided ~45 min

Project: Diagnose CaseNote's Ledger Gaps

Meridian Legal Aid Network's fictional intake assistant, CaseNote, has been running for three months on nothing but a good prompt. You're given five real, specific facts about how it operates today — no attack, no exotic failure, just a team that shipped fast and never came back. Your task: diagnose which of the five ledger lines each fact belongs to, propose a concrete fix, and prioritize the order you'd tackle them in, with real reasoning.

Why this project, not something more open-ended A first project that asked "build a context-engineered feature" before you'd practiced diagnosing gaps in an existing one would skip the more foundational skill. Diagnosis is what every later chapter's hands-on work depends on; building new systems with the missing lines already filled in is what Chapters 2-12 have you practice, one line at a time.
How to run it Download starter.py, fill in the diagnosis and prioritization, then run python3 starter.py to see a structural self-check (this task is open-ended, so it verifies completeness and well-formedness, not one exact wording). Compare against solution.py, then self-grade against RUBRIC.md.
starter.py solution.py (reference) RUBRIC.md README.md

What you're given

Five numbered facts about CaseNote's current operation — how its system prompt has grown, how retrieved articles never get evicted, how it handles a long intake transcript, how it handles memory across sessions, and how it budgets its own response.

What you produce

For each fact: the ledger line it maps to, the evidence in your own words, and one concrete engineering fix. Then a prioritized order for all five fixes, with a real justification — the same shape as the lesson's own Brackwater walkthrough table, applied by you, to a fresh system.

Passing bar

16/20 (80%) or higher on RUBRIC.md's five criteria, with no single criterion scoring 0. solution.py is one complete, valid reference diagnosis scoring a full 20/20 — not the only correct wording, since this project is intentionally open-ended.
